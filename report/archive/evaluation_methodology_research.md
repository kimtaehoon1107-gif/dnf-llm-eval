# 평가 방법론 근거 정리

작성일: 2026-05-27

## 1. 참고 문헌

본 프로젝트의 평가 설계는 다음 연구 흐름을 참고한다.

### HELM: Holistic Evaluation of Language Models

HELM은 언어모델을 단일 정확도만으로 평가하지 않고, 사용 시나리오와 여러 평가 지표를 함께 고려해야 한다는 관점을 제시한다. 특히 accuracy 외에도 calibration, robustness, fairness, bias, toxicity, efficiency 등을 함께 보는 multi-metric 접근을 강조한다.

본 프로젝트 적용:

- 게임 문서 Q&A에서도 단순 정답 여부만 보지 않는다.
- 정확성, 근거성, 완전성, 환각 방지, 범위 통제, 표현 품질을 함께 평가한다.
- 모델의 장단점을 질문 유형별로 분석한다.

출처: https://arxiv.org/abs/2211.09110

### RAGAS: Automated Evaluation of Retrieval Augmented Generation

RAGAS는 RAG 시스템 평가에서 검색된 문맥의 관련성, 모델이 문맥을 충실히 활용하는지, 생성 답변 자체의 품질을 구분해 평가해야 한다고 본다.

본 프로젝트 적용:

- `근거성`: 답변이 제공 문서에 의해 뒷받침되는가?
- `사용자 의도 적합성`: 답변이 질문 의도에 맞는가?
- `문서 근거 연결`: 질문별 evidence를 기준으로 답변을 평가한다.

출처: https://arxiv.org/abs/2309.15217

### ARES: Automated Evaluation Framework for RAG Systems

ARES는 RAG 평가 차원을 context relevance, answer faithfulness, answer relevance로 나누고, 경량 LM judge와 소량의 인간 주석을 함께 활용하는 방식을 제안한다.

본 프로젝트 적용:

- 평가 차원을 문서 관련성, 답변 충실성, 질문 관련성으로 나눠 해석한다.
- 완전 자동 평가보다 기준 정답과 사람의 평가 메모를 포함해 작은 데이터셋에서도 설명 가능한 평가를 목표로 한다.
- 경량 모델은 "평가 대상 모델"로 사용하고, 최종 판정은 기준 정답과 루브릭으로 수행한다.

출처: https://arxiv.org/abs/2311.09476

### FActScore

FActScore는 긴 답변을 원자적 사실 단위로 나누고, 각 사실이 신뢰 가능한 지식 출처에 의해 뒷받침되는지 계산하는 방식이다.

본 프로젝트 적용:

- 모델 답변 안의 수치, 조건, 제한, NPC명, 아이템명을 개별 사실로 본다.
- 하나의 답변이 대체로 맞아도 핵심 수치 하나가 틀리면 정확성에서 감점한다.
- 환각 여부는 "문서 근거가 없는 사실을 추가했는가"로 판단한다.

출처: https://arxiv.org/abs/2305.14251

## 2. 본 프로젝트의 평가척도 설계

게임 패치노트/업데이트 문서는 다음 특성이 있다.

- 수치 정보가 많다: 명성, 피로도, 구매 가격, 제한 횟수, 초기화 시간
- 조건 정보가 많다: 계정당, 월 단위, 주간 단위, 특정 NPC, 특정 던전
- 문서 버전 차이가 중요하다: 퍼스트 서버 내용은 라이브 서버에서 변경될 수 있다.
- 유저 질문은 짧지만 답변에는 예외 조건이 필요할 수 있다.
- 문서 밖 게임 지식이나 추측이 섞이면 잘못된 안내가 된다.

따라서 본 프로젝트는 다음 7개 평가척도를 사용한다.

| 평가척도 | 정의 | 도입 이유 |
|---|---|---|
| 정확성 | 원문과 답변의 사실 일치도 | 게임 업데이트는 수치/조건 오류가 치명적이다 |
| 근거성 | 답변이 제공 문서 evidence로 뒷받침되는 정도 | 문서 기반 QA의 핵심은 출처 기반 답변이다 |
| 완전성 | 필요한 조건과 예외를 빠짐없이 포함하는 정도 | 일부 조건 누락은 유저 오해를 만든다 |
| 사용자 의도 적합성 | 질문 의도에 직접 답하는 정도 | 장황하거나 엉뚱한 답변을 방지한다 |
| 환각 방지 | 문서에 없는 사실을 추가하지 않는 정도 | 게임 외 지식/추측 생성을 막는다 |
| 범위 통제 | 문서 범위 밖 질문을 거절하는 정도 | 도메인 제한형 어시스턴트의 안전장치다 |
| 표현 품질 | 유저가 이해하기 쉬운 한국어 답변인지 | 실제 서비스 응답 품질과 연결된다 |

## 3. 스코어링 방식

각 항목은 0~3점으로 평가한다.

| 점수 | 의미 |
|---|---|
| 3 | 기준을 충족한다 |
| 2 | 대체로 충족하지만 일부 누락이나 약점이 있다 |
| 1 | 부분적으로만 충족한다 |
| 0 | 충족하지 못한다 |

총점은 21점 만점이다.

판정 기준:

| 총점 | 판정 |
|---|---|
| 19~21 | 우수 |
| 15~18 | 보통 |
| 10~14 | 미흡 |
| 0~9 | 실패 |

단, 범위 밖 질문은 총점보다 `범위 통제`와 `환각 방지`를 우선적으로 본다. 게임 외 질문에 그럴듯한 답을 생성하면 정답처럼 보이더라도 실패로 판정한다.

## 4. 품질 체크리스트

평가자는 각 답변에 대해 다음을 확인한다.

- 원문 수치를 바꾸지 않았는가?
- 아이템명, NPC명, 콘텐츠명을 정확히 썼는가?
- 계정당/월/주간/무료 1회 같은 제한 조건을 빠뜨리지 않았는가?
- 퍼스트 서버 내용을 확정 정보처럼 말하지 않았는가?
- 문서에 없는 추천, 효율 분석, 개인 의견을 추가하지 않았는가?
- 질문이 게임 외 주제일 때 답변을 제한했는가?
- 답변이 너무 장황하거나 유저 질문과 무관하지 않은가?

## 5. 객관성 확보 방법

본 프로젝트는 작은 규모의 평가이므로 다음 방식으로 객관성을 높인다.

- 모든 질문에 기준 정답과 evidence를 붙인다.
- 평가 항목별 0~3점 기준을 문서화한다.
- 감점 사유를 `evaluator_note`에 남긴다.
- 질문 유형별 평균 점수를 따로 계산한다.
- 범위 밖 질문을 별도로 두어 도메인 제한 능력을 확인한다.
- 동일 질문 세트로 여러 경량 모델을 비교할 수 있게 한다.
