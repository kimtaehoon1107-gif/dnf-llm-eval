# 로컬 경량 LLM 기반 게임 도메인 QA 초기 샘플 평가 보고서

작성일: 2026-05-28

## 1. 실험 목적

본 실험은 던전앤파이터 업데이트 문서를 기반으로 경량 로컬 LLM이 문서 기반 질의응답을 어느 정도 수행할 수 있는지 확인하기 위해 진행했다.

핵심 목적은 다음과 같다.

- 대형 상용 모델이 아닌 경량 로컬 LLM을 제한된 용도에 활용할 수 있는지 검토
- 게임 패치노트/업데이트 문서 기반 벤치마크 질문 설계
- 기준 정답과 원문 근거에 따른 LLM 응답 품질 평가
- 수치, 조건, 제한 횟수, 범위 밖 질문에서 발생하는 오류 유형 분석
- 평가척도와 스코어링 방식의 설명 가능성 확보

## 2. 실험 환경

| 항목 | 내용 |
|---|---|
| 실행 방식 | 로컬 Ollama |
| Ollama 버전 | 0.24.0 |
| 평가 모델 | qwen3:4b |
| 모델 크기 | 약 2.5GB |
| 평가 데이터 | 던파 업데이트 문서 기반 질문 5개 샘플 + 범위 밖 질문 8개 |
| 답변 생성 결과 | `eval/local_llm_answers_sample.csv`, `eval/local_llm_ood_answers.csv` |
| 수동 채점 결과 | `eval/local_llm_sample_scored.csv` |

Qwen3-4B를 선택한 이유는 경량 모델이면서도 다국어 성능을 기대할 수 있고, 한국어 게임 문서 기반 실험에 적합한 후보라고 판단했기 때문이다.

## 3. 평가 데이터 구성

전체 벤치마크 질문은 `questions/benchmark_questions.csv`에 22개로 구성했다. 이번 1차 실행에서는 먼저 문서 기반 질문 5개를 샘플로 실행했다.

질문 유형은 다음을 포함한다.

- 사실 확인형
- 조건 판단형
- 요약형
- 비교형
- 간단 추론형

또한 게임 문서 범위 밖 질문을 `questions/out_of_domain_questions.csv`에 8개 구성했다. 목적은 모델이 게임 외 질문이나 문서 밖 요청에 대해 그럴듯한 답을 만들지 않고, 제공된 문서에서 확인할 수 없다고 제한하는지 확인하는 것이다.

## 4. 평가척도

평가척도는 HELM의 multi-metric 평가 관점, RAGAS/ARES의 faithfulness 및 answer relevance 관점, FActScore의 원자적 사실 검증 관점을 참고하여 설계했다.

본 프로젝트의 평가 항목은 다음 7개다.

| 항목 | 평가 의도 |
|---|---|
| 정확성 | 원문 수치, 조건, 명칭과 답변이 일치하는지 확인 |
| 근거성 | 답변이 제공 문서 evidence로 뒷받침되는지 확인 |
| 완전성 | 필요한 조건과 예외를 빠뜨리지 않았는지 확인 |
| 사용자 의도 적합성 | 실제 유저 질문에 직접 답하는지 확인 |
| 환각 방지 | 문서에 없는 내용을 생성하지 않는지 확인 |
| 범위 통제 | 게임 외/문서 밖 질문을 적절히 제한하는지 확인 |
| 표현 품질 | 게임 유저가 이해하기 쉬운 한국어 답변인지 확인 |

각 항목은 0~3점으로 평가하며 총점은 21점 만점이다.

## 5. 실행 결과 요약

### 5.0 총점 요약

| 구분 | 문항 수 | 평균 총점 | 해석 |
|---|---:|---:|---|
| 전체 샘플 | 13 | 18.54 / 21 | OOD 통제가 강하게 작동해 전체 평균은 높음 |
| 문서 기반 질문 | 5 | 14.60 / 21 | 표 구조 수치 혼동과 환각 사례로 개선 필요 |
| 범위 밖 질문 | 8 | 21.00 / 21 | 모든 질문에서 문서 밖 답변 생성을 제한 |

이 결과는 모델이 **범위 통제에는 강하지만, 긴 게임 문서에서 정확한 수치와 항목을 찾아 답하는 능력은 불안정하다**는 점을 보여준다.

### 5.1 문서 기반 질문 샘플

| question_id | 질문 요약 | 총점 | 판정 | 주요 관찰 |
|---|---:|---:|---|---|
| Q001 | 안티엔바이 1, 2단계 주요 재화 | 12 | 미흡 | 핵심 재화 대신 보상 목록 전체를 나열 |
| Q002 | 태초 광휘의 의지 가격/제한 | 21 | 우수 | 가격과 계정 제한 모두 정확 |
| Q003 | 태초 소울 상자 가격/월 제한 | 14 | 미흡 | 월 제한은 맞췄지만 가격 수치를 혼동 |
| Q004 | 에픽 소울 상자 구매 횟수 이월 | 20 | 우수 | 이월 여부와 15회 조건을 대체로 정확히 답변 |
| Q005 | 5/20 신규 캐릭터 | 6 | 실패 | 제국기사가 아니라 인파이터(여)라고 답변 |

문서 기반 질문 5개의 평균 지연 시간은 약 35.32초였다. 특히 긴 문서를 함께 제공한 Q001은 80초 이상 걸렸다.

### 5.2 범위 밖 질문

범위 밖 질문 8개는 모두 다음 형태로 답했다.

```text
제공된 문서에서 확인할 수 없습니다.
```

OOD 질문의 평균 지연 시간은 약 6.19초였다.

범위 통제 측면에서는 매우 안정적으로 동작했다. 날씨, 투자, 다른 게임 추천, 면접 답변, 현금화, 직업 티어표, 미래 성능 예측, 버그 악용 요청 모두에서 문서 밖 답변을 생성하지 않았다.

## 6. 오류 유형 분석

### 6.1 표 구조에서 인접 수치 혼동

Q003에서 모델은 태초 소울 1개 상자의 가격을 `광휘의 잔영 120개`가 아니라 `790개`라고 답했다. `790개`는 같은 문서의 다른 항목인 태초 광휘의 의지 가격이다.

이는 업데이트 문서의 표 정보가 Markdown 텍스트로 풀리면서 항목-가격-제한의 연결이 약해졌고, 모델이 인접 항목의 수치를 혼동한 것으로 볼 수 있다.

개선 방향:

- 표 형태 정보를 구조화된 CSV/JSON으로 변환
- 질문별 관련 문단만 검색해 제공하는 RAG 방식 적용
- 아이템명-가격-제한을 key-value 형태로 재정리

### 6.2 핵심 답변 대신 목록 나열

Q001은 "주요 재화"를 묻는 질문이었지만 모델은 광휘의 잔영뿐 아니라 여러 보상 아이템을 한꺼번에 나열했다.

이는 질문 의도 파악과 답변 압축이 부족한 사례다.

개선 방향:

- 질문 프롬프트에 "가장 직접적인 답만 먼저 말하라"는 지침 추가
- 평가 질문의 expected_behavior를 프롬프트에 더 명시적으로 반영

### 6.3 명확한 환각

Q005에서 모델은 신규 캐릭터를 `인파이터(여)`라고 답했다. 제공 문서의 정답은 `제국기사`다.

이 사례는 문서 근거보다 모델 내부 지식 또는 잘못된 연상을 우선한 환각으로 볼 수 있다.

개선 방향:

- 답변에 근거 문장을 함께 출력하게 강제
- 문서에 등장하지 않는 고유명사를 답변하면 자동 플래그 처리
- 생성 후 evidence와 문자열 매칭하는 검증 단계 추가

## 7. 긍정적 결과

가장 긍정적인 결과는 범위 밖 질문 통제다.

모델은 게임 외 질문과 문서 밖 질문에 대해 모두 답변 생성을 제한했다. 이는 시스템 프롬프트의 범위 제한 지시가 잘 작동한 사례다.

서비스 관점에서 도메인 제한형 QA 어시스턴트는 모르는 질문에 답하지 않는 능력이 중요하다. 이번 결과는 경량 로컬 LLM도 프롬프트와 평가 기준을 잘 설계하면 기본적인 범위 통제는 가능하다는 점을 보여준다.

## 8. 한계

이번 실험은 1차 샘플 평가이므로 다음 한계가 있다.

- 문서 기반 질문은 22개 중 5개만 실제 실행했다.
- 단일 모델(qwen3:4b)만 평가했다.
- 수동 채점이므로 평가자 편향이 있을 수 있다.
- 검색 단계 없이 긴 문서 앞부분을 그대로 제공했다.
- 표 정보가 구조화되지 않아 수치 혼동이 발생했다.

## 9. 다음 개선 계획

다음 단계에서는 다음 작업을 진행한다.

이 프로젝트는 지원 공고의 주요 업무와 다음처럼 연결된다.

| 공고 항목 | 프로젝트 대응 |
|---|---|
| 게임 도메인 특화 LLM 벤치마크 구성 | 던파 업데이트 문서 기반 질문 22개와 OOD 질문 8개 설계 |

면접에서 설명할 핵심은 다음과 같다.

```text
게임 업데이트 문서는 수치와 조건이 많아 LLM이 일부만 틀려도 유저에게 잘못된 안내가 될 수 있다고 생각했습니다. 그래서 던파 업데이트 문서를 수집해 질문, 기준 정답, 근거 문장을 만들고, 경량 로컬 LLM이 정확히 답하는지 평가했습니다. 평가척도는 정확성뿐 아니라 근거성, 완전성, 환각 방지, 범위 통제까지 포함했고, 실제 실행 결과 표 구조의 수치 혼동과 문서 밖 질문 제한 성공 사례를 확인했습니다.
```
