# 로컬 경량 LLM 평가 실험 계획

작성일: 2026-05-27

## 1. 추천 방향

본 프로젝트는 공개 웹 데모보다 **로컬 경량 LLM 평가 실험 + GitHub 코드/결과 공개** 방식으로 진행한다.

이유는 다음과 같다.

- 지원 공고의 핵심은 웹서비스 배포가 아니라 LLM 평가 및 데이터 기반 문제 분석 경험이다.
- 로컬 LLM을 사용하면 제한된 자원 환경에서 평가 파이프라인을 설계했다는 스토리를 만들 수 있다.
- 질문, 기준 정답, 근거, 평가척도, 채점 결과를 모두 공개하면 면접관은 실행 여부와 별개로 사고 과정을 확인할 수 있다.
- 실시간 웹 데모는 환경 의존성이 크지만, CSV/보고서/코드는 재현성과 설명력이 높다.

따라서 최종 산출물은 다음 형태가 가장 적합하다.

```text
1. 데이터 수집 코드
2. 게임 문서 기반 벤치마크 질문
3. 로컬 LLM 답변 생성 스크립트
4. 평가 루브릭
5. 샘플 평가 결과
6. 오류 유형 분석 보고서
```

## 2. 실험 스토리

본 실험의 핵심 스토리는 다음과 같다.

> ChatGPT 같은 대형 모델은 성능이 좋지만 자원 사용량과 비용이 크다. 게임 서비스의 문서 기반 Q&A처럼 용도가 제한된 작업에서는 경량 로컬 LLM도 활용 가능성이 있다. 다만 실제 서비스에 쓰려면 모델이 문서 근거를 지키는지, 수치와 조건을 정확히 답하는지, 게임 외 질문을 거절하는지 평가해야 한다. 따라서 던파 업데이트 문서 기반으로 질문-정답-근거 데이터셋을 만들고, 경량 LLM의 답변을 정확성, 근거성, 완전성, 범위 통제, 환각 방지 기준으로 평가한다.

이 스토리는 공고의 다음 항목과 직접 연결된다.

- LLM 평가 또는 데이터 기반 문제 분석 경험
- 객관적인 성능 비교를 위한 평가 기준, 스코어링 방식, 품질 체크리스트 설계
- 게임 관련 문서 기반 유저 질문 시나리오와 벤치마크 질문 설계

## 3. 모델 선택

### 1순위: Qwen3-4B 계열

추천 모델은 Qwen3-4B 계열이다.

선정 이유:

- 4B 규모로 로컬 실행 가능한 경량 모델이다.
- Qwen3 Technical Report는 Qwen3가 성능, 효율성, 다국어 능력을 목표로 한 모델군이며 0.6B부터 235B까지 다양한 크기를 제공한다고 설명한다.
- Qwen3는 119개 언어/방언 지원을 언급하므로 한국어 게임 문서 실험에 더 적합한 후보로 볼 수 있다.
- Hugging Face의 Qwen3-4B 모델 카드는 4.0B 파라미터와 32K 기본 컨텍스트 길이를 제시한다.

실행 예시:

```powershell
ollama pull qwen3:4b
ollama run qwen3:4b
```

### 대안: Llama 3.2 3B 또는 1B

PC 자원이 부족하면 Llama 3.2 3B 또는 1B를 대안으로 사용한다.

Ollama 모델 페이지 기준으로 `llama3.2:latest`와 `llama3.2:3b`는 약 2.0GB, `llama3.2:1b`는 약 1.3GB로 표시된다. 1B 모델은 성능이 낮을 수 있지만 “자원 제약 환경에서 어디까지 가능한가”를 보여주는 비교군으로는 의미가 있다.

실행 예시:

```powershell
ollama pull llama3.2
ollama run llama3.2
```

## 4. 평가 대상

평가 대상은 두 종류로 나눈다.

### 4.1 문서 기반 질문

`questions/benchmark_questions.csv`에 있는 22개 질문을 사용한다.

질문 유형:

- 사실 확인형
- 조건 판단형
- 비교형
- 요약형
- 간단 추론형

각 질문은 기준 정답, 원문 근거, 기대 답변 방식을 포함한다.

### 4.2 범위 밖 질문

`questions/out_of_domain_questions.csv`에 있는 질문을 사용한다.

목적은 모델이 게임 문서와 무관한 질문에 답을 만들어내지 않고, 제공된 문서 범위 밖임을 명확히 말하는지 확인하는 것이다.

예시:

- 오늘 날씨 알려줘
- 메이플스토리 직업 추천해줘
- 넥슨 채용 면접 답변을 대신 써줘
- 광휘의 잔영으로 비트코인을 살 수 있어?

기대 답변:

```text
제공된 던파 업데이트 문서에서 확인할 수 없습니다.
```

## 5. 프롬프트 원칙

로컬 LLM에는 다음 원칙을 시스템 프롬프트로 부여한다.

```text
너는 던전앤파이터 업데이트 문서 기반 QA 어시스턴트다.
반드시 제공된 문서 내용만 근거로 답변한다.
문서에 없는 내용은 추측하지 않는다.
게임 문서 범위 밖 질문에는 "제공된 문서에서 확인할 수 없습니다."라고 답한다.
수치, 조건, 제한 횟수, 초기화 시점은 원문과 다르게 바꾸지 않는다.
답변은 한국어로 간결하게 작성한다.
```

## 6. 평가 항목

평가 항목은 다음 7개로 확장한다.

| 항목 | 이유 |
|---|---|
| 정확성 | 수치, 조건, 명칭이 원문과 일치하는지 확인 |
| 근거성 | 답변이 제공 문서에 의해 뒷받침되는지 확인 |
| 완전성 | 질문에 필요한 조건/예외를 빠뜨리지 않았는지 확인 |
| 사용자 의도 적합성 | 실제 유저 질문에 맞게 답하는지 확인 |
| 환각 방지 | 문서에 없는 내용을 생성하지 않는지 확인 |
| 범위 통제 | 게임 외 또는 문서 범위 밖 질문을 적절히 거절하는지 확인 |
| 표현 품질 | 게임 유저가 이해하기 쉬운지 확인 |

각 항목은 0~3점으로 평가한다.

## 7. 결과 분석 계획

실험 후 다음 관점으로 결과를 분석한다.

- 수치형 질문에서 오류가 발생하는가?
- 조건형 질문에서 구매 제한, 계정 단위, 초기화 시점을 누락하는가?
- 퍼스트 서버 정보를 라이브 서버 확정 정보처럼 답하는가?
- 문서에 없는 추천, 추측, 일반 지식을 덧붙이는가?
- 게임 외 질문을 거절하지 않고 답하려 하는가?
- 경량 모델이 자주 실패하는 질문 유형은 무엇인가?

## 9. 면접에서 설명할 핵심 문장

```text
대형 모델을 바로 쓰기보다, 게임 문서 기반 Q&A처럼 범위가 제한된 업무에서는 경량 로컬 LLM의 활용 가능성을 먼저 검증해보고 싶었습니다. 그래서 던파 업데이트 문서를 수집해 질문-정답-근거 데이터셋을 만들고, 로컬 LLM이 수치와 조건을 정확히 답하는지, 문서에 없는 내용을 환각하지 않는지, 게임 외 질문을 제한하는지 평가했습니다. 평가척도는 RAG 평가 연구의 faithfulness, answer relevance, context relevance 개념과 HELM의 multi-metric 평가 관점을 참고해 설계했습니다.
```
