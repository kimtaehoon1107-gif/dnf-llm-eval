# RAG 적용 후 로컬 경량 LLM 재평가 보고서

작성일: 2026-05-28

## 1. 목적

이 보고서는 기존 baseline 방식과 RAG 방식을 비교하기 위해 작성했다. baseline은 질문에 연결된 문서 전체를 qwen3:4b에 제공하는 방식이었고, RAG 방식은 문서를 작은 chunk로 나눈 뒤 질문과 관련 높은 근거 chunk만 검색해 모델에 제공하는 방식이다.

핵심 질문은 다음과 같다.

> 긴 게임 업데이트 문서 전체를 넣는 것보다, 질문 관련 근거만 검색해 제공하면 경량 로컬 LLM의 답변 품질이 개선되는가?

## 2. 구현 방식

RAG는 `scripts/run_rag_local_llm_eval.py`로 구현했다.

구성은 다음과 같다.

1. `data/processed_md`의 Markdown 문서를 line-window chunk로 분할
2. 한국어/영문/숫자 토큰 및 한글 n-gram 기반 토큰화
3. BM25 점수와 핵심어 coverage bonus를 이용해 관련 chunk 검색
4. 표형 데이터 질문을 위해 가격, 구매 제한, 시간, 명성, 피로도 관련 intent bonus 추가
5. 검색된 근거 chunk 8개를 qwen3:4b에 제공
6. 모델은 검색된 근거에 직접 답이 없으면 확인 불가로 답하도록 제한

공정 비교를 위해 benchmark 질문은 각 질문의 `doc_id` 안에서 chunk를 검색했다. 이는 baseline도 질문별 `doc_id` 문서를 통째로 넣었기 때문에 같은 문서 조건에서 “전체 문서 입력 vs 관련 chunk 입력”을 비교하기 위함이다.

## 3. 산출물

| 파일 | 설명 |

## 4. 전체 결과 비교

| 방식 | 전체 평균 | 문서 기반 질문 평균 | OOD 평균 |
|---|---:|---:|---:|
| Baseline: 문서 전체 입력 | 13.87 / 21 | 11.27 / 21 | 21.00 / 21 |
| RAG: 관련 chunk 입력 | 19.43 / 21 | 18.86 / 21 | 21.00 / 21 |

RAG 적용 후 문서 기반 질문 평균은 **11.27점에서 18.86점으로 7.59점 상승**했다.

OOD 질문은 baseline과 RAG 모두 21점으로 동일하게 높았다. 즉, 범위 통제는 기존 프롬프트만으로도 잘 작동했으며, RAG의 주요 개선 효과는 문서 기반 질문의 정확성과 근거성에서 나타났다.

## 5. 문서별 결과 비교

| 문서 | Baseline 평균 | RAG 평균 | 변화 |
|---|---:|---:|---:|
| DOC-01 | 16.75 | 15.00 | -1.75 |
| DOC-02 | 5.25 | 17.00 | +11.75 |
| DOC-03 | 21.00 | 21.00 | 0.00 |
| DOC-04 | 5.25 | 19.25 | +14.00 |
| DOC-05 | 6.80 | 21.00 | +14.20 |

DOC-02, DOC-04, DOC-05에서 큰 개선이 있었다. 이 문서들은 길고 섹션이 많아 baseline에서 모델이 관련 근거를 찾지 못하거나 과잉 거절하는 문제가 컸다. RAG 적용 후 관련 chunk만 제공되면서 신규 캐릭터, HP 조정, 입장 조건, 초기화 시점 같은 정보를 정확히 답했다.

DOC-01은 오히려 평균이 약간 낮아졌다. 표형 상점 데이터에서 chunk 검색은 관련 영역을 찾았지만, 모델이 가격/제한 정보를 일부 누락하거나 확인 불가로 답한 사례가 남았다. 이는 표 데이터를 단순 line chunk가 아니라 구조화된 key-value 형태로 변환해야 함을 보여준다.

## 6. 대표 개선 사례

### Q005: 신규 캐릭터 질문

- 기준 정답: 신규 캐릭터 제국기사
- baseline 답변: 인파이터(여)
- RAG 답변: 제국기사

RAG가 신규 캐릭터 추가 문단을 직접 제공하면서 환각이 제거됐다.

### Q014: 최후의 과업 HP 조정

- 기준 정답: 몬스터 HP 10% 일괄 하향
- baseline 답변: 확인 불가
- RAG 답변: 몬스터 HP 10% 일괄 하향, 성화 작열 HP 감소량 40%에서 30% 조정

baseline은 문서 앞부분의 디렉터 코멘트 정보를 찾지 못했지만, RAG는 관련 문단을 제공해 정답을 생성했다.

### Q019: 피로도와 제한 시간

- 기준 정답: 피로도 30, 제한 시간 60분
- baseline 답변: 피로도 없음, 제한 시간 확인 불가
- RAG 답변: 피로도 30, 제한 시간 60분

baseline은 시나리오 던전 정보와 상급 던전 정보를 혼동했지만, RAG는 콘텐츠 정보와 콘텐츠 규칙 chunk를 함께 제공해 정확히 답했다.

## 7. 남은 오류

### Q002: 검색 근거는 있었지만 모델이 확인 불가로 답변

검색된 근거에는 `태초 광휘의 의지`, `광휘의 잔영 790개`, `계정당 1회`가 포함되어 있었다. 하지만 모델은 직접적인 정보가 없다고 답했다.

이는 retrieval 실패가 아니라, 표형 텍스트를 모델이 key-value 관계로 해석하지 못한 문제다.

### Q003: 가격 누락

모델은 월 4회 제한은 맞췄지만, 가격 `광휘의 잔영 120개`는 누락했다. 이 역시 표형 데이터 해석 문제다.

### Q007: 과잉 거절

덱 브레이커 효과가 근거에 있었지만 모델이 확인 불가로 답했다. 검색된 chunk가 너무 넓거나 관련 스킬 설명보다 다른 스킬 정보가 함께 들어가 모델이 답변을 보수적으로 제한한 것으로 보인다.

## 8. 결론

RAG는 baseline의 가장 큰 약점이었던 긴 문서 탐색 실패와 과잉 거절 문제를 크게 줄였다.

특히 DOC-04와 DOC-05처럼 긴 문서에서는 RAG 적용 후 평균 점수가 5~6점대에서 19~21점대로 상승했다. 이는 경량 로컬 LLM 자체의 성능만 보는 것보다, 어떤 근거를 어떻게 제공하느냐가 문서 기반 QA 품질에 큰 영향을 준다는 것을 보여준다.

다만 표형 데이터는 여전히 약점으로 남았다. 이를 보완하기 위해 후속 단계에서 표를 Markdown line chunk로만 제공하지 않고, 아이템명-가격-구매 제한을 구조화된 JSON 형태로 변환해 RAG context에 함께 넣는 옵션을 추가했다.

## 9. 지원 직무 연결

이 단계는 지원 공고의 “데이터 기반 문제 분석”과 “모델 개선을 위한 인사이트 전달”을 직접 보여준다.

설명할 수 있는 흐름은 다음과 같다.

```text
1차 baseline 평가에서는 문서 전체를 입력했을 때 경량 LLM이 긴 게임 문서에서 근거를 찾지 못하고 과잉 거절하는 문제가 나타났습니다.
이를 해결하기 위해 문서를 chunk로 나누고 질문 관련 근거만 검색해 제공하는 RAG 단계를 추가했습니다.
재평가 결과 문서 기반 질문 평균 점수가 11.27점에서 18.86점으로 상승했고, 특히 최후의 과업처럼 긴 문서의 입장 조건·HP 조정·제한 시간 질문에서 큰 개선을 확인했습니다.
다만 상점 보상 표에서는 여전히 가격/제한 관계를 놓치는 문제가 있어, 후속 개선으로 표 데이터를 JSON으로 구조화하고 RAG 근거 앞에 결합하는 옵션을 추가했습니다.
```
