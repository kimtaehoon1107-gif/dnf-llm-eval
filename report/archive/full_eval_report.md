# 로컬 경량 LLM 기반 게임 도메인 QA 전체 평가 보고서

작성일: 2026-05-28

## 1. 목적

본 평가는 던전앤파이터 업데이트 문서 기반 질문에 대해 경량 로컬 LLM이 얼마나 정확히 답할 수 있는지 확인하기 위해 수행했다. 단순 챗봇 데모가 아니라, 게임 문서 기반 벤치마크 질문과 평가 루브릭을 설계하고 모델의 실패 유형을 데이터로 분석하는 것이 목적이다.

## 3. 평가 기준

평가 기준은 정확성, 근거성, 완전성, 사용자 의도 적합성, 환각 방지, 범위 통제, 표현 품질의 7개 항목으로 구성했다. 각 항목은 0~3점이며 총점은 21점이다.

이 기준은 HELM의 multi-metric 평가 관점, RAGAS/ARES의 faithfulness 및 answer relevance 관점, FActScore의 사실 단위 검증 관점을 참고해 게임 패치노트 평가에 맞게 재구성했다.

## 7. 오류 유형 분석

### 7.1 수치 혼동

Q003에서 모델은 `태초 소울 1개 상자` 가격을 `광휘의 잔영 120개`가 아니라 `790개`라고 답했다. 790개는 같은 표의 다른 항목인 `태초 광휘의 의지` 가격이다.

이는 Markdown으로 풀린 표에서 아이템명-가격-제한의 연결이 약해졌기 때문에 발생한 것으로 보인다.

### 7.2 환각

Q005에서 신규 캐릭터를 `제국기사`가 아니라 `인파이터(여)`라고 답했다. Q006에서는 브레이커를 제국기사의 첫 번째 전직이 아니라 문서에 없는 관계로 설명했다.

이는 문서 근거보다 모델 내부 지식 또는 주변 섹션의 잘못된 연상을 우선한 사례다.

### 7.3 과잉 거절

Q007, Q008, Q014, Q015, Q016, Q018, Q020, Q021 등에서는 문서 안에 정답이 있음에도 `제공된 문서에서 확인할 수 없습니다`라고 답했다.

범위 통제 프롬프트가 OOD 질문에는 잘 작동했지만, 긴 문서 내 검색 실패 상황에서는 실제 정답이 있는 질문까지 거절하는 부작용이 있었다.

### 7.4 긴 문서에서 관련 섹션 탐색 실패

DOC-04의 HP 조정 정보는 문서 앞부분에 명확히 있었지만 모델은 이를 찾지 못했다. DOC-05의 입장 명성, 피로도, 제한 시간, 초기화 시점도 문서 안에 있었으나 다수 실패했다.

단순히 문서 전체를 프롬프트에 넣는 방식은 경량 모델에게 효율적이지 않다는 점을 확인했다.

## 8. 긍정적 결과

범위 밖 질문 8개는 모두 성공적으로 제한했다.

질문 예시는 다음과 같다.

- 오늘 서울 날씨 알려줘
- 비트코인 지금 사도 될까?
- 메이플스토리 직업 추천해줘
- 최후의 과업 직업 티어표 만들어줘
- 버그 악용 방법 알려줘

모델은 모두 `제공된 문서에서 확인할 수 없습니다` 형태로 답했다. 이는 도메인 제한형 QA 어시스턴트에서 중요한 안전장치가 프롬프트만으로도 어느 정도 작동할 수 있음을 보여준다.

## 9. 개선 제안

다음 개선은 단순히 모델을 키우는 것보다 데이터 제공 방식을 바꾸는 쪽이 우선이다.

1. 문서 전체가 아니라 질문과 관련된 문단만 검색해 제공한다.
2. 표 정보를 Markdown 텍스트가 아니라 구조화된 JSON/CSV로 변환한다.
3. 답변 생성 후 고유명사와 수치가 evidence에 존재하는지 검증한다.
4. OOD 거절 프롬프트를 유지하되, 문서 내 검색 실패와 실제 범위 밖 질문을 구분한다.
5. 동일 질문으로 더 작은 모델 또는 다른 경량 모델과 비교한다.
