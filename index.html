Evaluation Design

RAGAS-style 관점은 참고했지만, 게임 운영 문서에 맞춰 도메인 루브릭을 직접 설계했습니다.

Benchmark

문서 기반 질문 22개

패치노트, 상점표, 조건 판단, 비교 질문을 섞어 실제 이용자 질문에 가깝게 구성했습니다.

Rubric

7개 수동 평가 항목

정확성, 근거 충실성, 완전성, 의도 적합성, 환각 억제, 범위 통제, 표현 품질로 채점했습니다.

Safety

OOD와 공격 질문 통제

날씨, 투자, 다른 게임, 현금화, 버그 악용, prompt leakage 질문을 범위 밖으로 제한했습니다.

What Changed

성공 결과만 보여주지 않고, 실패 원인을 검색, 구조화, 생성 모델, safety로 나눠 기록했습니다.

Issue Finding Response
긴 문서 근거 누락 Non-RAG baseline은 최신 패치노트 세부 조건을 안정적으로 찾지 못했습니다. RAG를 붙여 문서 질문 평균을 11.27에서 18.86으로 개선했습니다.
표형 정보 혼입 상점표에서 인접 상품의 가격, 구매 제한이 섞이는 문제가 있었습니다. `shop_items.json`을 만들어 표 행 단위 근거를 별도 제공했습니다.
서비스 답변 형식 실패 BGE-M3 고정 ablation에서 `qwen3:4b`는 format proxy가 9 / 22였고 meta reasoning이 13건 발생했습니다. instruct variant 적용 후 format proxy를 22 / 22로 개선하고 meta reasoning을 0건으로 줄였습니다.
Safety gate 우회 복합 조건 규칙은 paraphrase set을 10 / 10 차단했지만, 직접 키워드를 피한 stealth set은 0 / 10만 사전 차단했습니다. 규칙 기반 1차 필터의 한계를 기록하고, semantic classifier와 output safety check를 후속 개선으로 남겼습니다.

Next Extension

현재 결과는 offline benchmark이며, 실제 서비스 단계에서는 평가셋 갱신과 운영 로그 추적을 붙여 확장할 수 있습니다.

Dynamic Eval

패치 주기 기반 평가셋 갱신

새 패치노트가 올라오면 변경점을 추출하고, 질문과 기준 정답 후보를 다시 만들어 평가셋이 낡지 않도록 확장합니다.

Auto Judge

자동 평가는 보조 지표로 사용

RAGAS, DeepEval, LLM-as-a-Judge를 최종 판정자가 아니라 검색 적합성, 근거 충실성, 환각 여부를 빠르게 점검하는 보조 평가자로 둡니다.

Observability

질문부터 피드백까지 추적

question_id, retrieved_chunk_ids, answer, latency, safety decision, user feedback을 기록해 offline 평가와 실제 로그를 연결합니다.
